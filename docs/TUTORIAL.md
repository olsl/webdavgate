## 一、问题：为什么手机上 WebDAV 还是不能用

上篇方案的核心是 Cloudflare 页面规则的 **302 跳转**：

```
dav.xxx.xyz  --302-->  dav.stun.xxx.xyz:动态端口
```

浏览器对这个流程毫无压力（自动跟随跳转），但 **CX 文件管理器、OttPlayer、AIMP 等大量手机 App 的 WebDAV 模块并不支持 302 跳转**：

| 场景 | 表现 |
|------|------|
| 直接填 CF 域名 | 大多数 App 连目录都刷不出来 |
| 手动查端口改填 `dav.stun.xxx.xyz:18234` | 能用了！但 NAS/LUCKY 一重启端口就变，又得查一遍、改一遍 |
| 个别 App 能跟 302 | 只能浏览/下载；**上传直接失败**（客户端不会把文件重新发给跳转后的新地址） |

这不是协议本身的问题——WebDAV 就是标准 HTTP，跳转完全兼容。纯粹是很多客户端**没处理重定向响应**，而这一场景偏偏只有我们这种 STUN 穿透用户才会碰到。

## 二、解决思路：在手机上装一个"本地反代"

上篇在 lucky 里给浏览器做了服务端反代，思路同样可以搬到手机侧：

```
CX文件管理器 ──127.0.0.1:8888──▶ WebDavGate(手机本地) ──自动消化302──▶ NAS直连
     （永远只配固定域名）          · 首次请求学习真实端口        └──────┘
                                  · 缓存直连地址（2分钟有效）
                                  · 端口漂移自动重新学习
```

**WebDavGate** 就是这样一个小工具：运行在你的安卓手机上，监听本机 8888 端口，把 CX 发来的所有 WebDAV 请求原样转发给 NAS——途中它替你干三件事：

1. **自动跟随 302/307**：第一次访问时顺藤摸瓜找到当前真实的 STUN 直连地址；
2. **缓存 + 失效重学**：直连地址缓存 2 分钟，端口漂移后最多几秒内自动切换到新端口，全程无感；
3. **补齐客户端缺陷**：上传走流式转发不吃内存、MOVE/COPY 的 Destination 地址自动改写（否则 NAS 返回 502）、跨域跳转时清理认证头（兼容 Alist/OSS 302 直链下载）。

所有流量都在你自己的手机和你的 NAS 之间传输，**不经过任何第三方中转服务器**，网关只监听 127.0.0.1 本机回环，无泄露风险。

## 三、安装与配置（两分钟）

### 1. 安装

从 GitHub Releases 下载 APK 安装：（发布后补充下载地址）

### 2. 添加节点

打开 APP → 点击右下角 ➕ 添加节点：

| 配置项 | 填什么 | 说明 |
|--------|--------|------|
| 名称 | 随便起，如 `我的NAS` | 仅用于展示 |
| CF 入口地址 | `https://dav.xxx.xyz/dav` | **填穿透前的固定域名**（就是你在 CX 里曾经要手改的那个），带实际 WebDAV 路径 |
| 本地端口 | `8888` | 默认即可，被占用才需要换 |

多个节点可以用不同本地端口并存（例如 NAS 一个、Alist 一个）。

### 3. 启动网关

回到主页点击**「启动网关」**按钮，看到状态点变绿即运行中。
首次启动建议按提示**允许"忽略电池优化"**——防止 ColorOS/MIUI 等系统把后台进程冻结导致网关短暂无响应。

### 4. 配置 CX 文件管理器

CX 里添加网络存储（WebDAV）：

```
服务器：127.0.0.1:8888      ← 永远不变
账号/密码：NAS 的账号密码    ← 和以前一样
```

> OttPlayer、ES文件浏览器、Solid Explorer 等 WebDAV 客户端同理：全部指向 `127.0.0.1:8888` 即可。

完成。以后无论 lucky 端口怎么漂移，CX 里**再也不用动任何配置**。

## 四、实际效果

| 操作 | 效果 |
|------|------|
| 浏览目录 | 直连速度，与手填 STUN 地址一致 |
| 上传大文件 | 流式转发，速度等同直连（实测取决于 Wi-Fi 与上行） |
| NAS 重启/换端口 | 无需任何操作，最多几秒自动恢复 |

## 五、常见问题

**Q：手机重启 / 杀后台后要重新开吗？**
A：前台服务常驻（通知栏可见）。配合电池白名单与锁保持后台不被冻结，开机后进入 APP 点一次启动即可。

**Q：为什么有时首次连接慢一两秒？**
A：缓存过期后需要先访问一次 CF 入口重新学习端口。可把缓存理解为"有效期 2 分钟的高速通道"，过期重建很快。

**Q：电脑上也能用吗？**
A：目前是安卓 APP。PC 端可以直接用 lucky 自带的本地反向代理（参考《LUCKY STUN穿透》相关教程）；路由器则由 lucky 完成服务端部分。

**Q：会不会很耗电？**
A：空闲时几乎为零，仅在传输文件时有正常网络开销。APP 使用 WakeLock 保证可用性，介意可在不用网关时随时停止。

## 六、结语

至此整套链路完全成型：

```
手机CX ──▶ WebDavGate(本地消化302) ──▶ lucky直连端口 ◀── lucky webhook 自动更新 ◀── CF页面规则(302)
```

- NAS 侧：lucky 负责 STUN 打洞 + CF 动态端口隐藏（见上篇）
- 手机侧：WebDavGate 负责 WebDAV 兼容 + 端口自适应（本文）

两边各司其职，谁也不用再手动查端口改配置了。
